SARA DESKTOP
Backend, penyimpanan, dan alur kerja

1. Arsitektur
- Sara adalah aplikasi desktop Linux. Tidak ada server/backend Sara sendiri; aplikasi mengirim request langsung ke Google Gemini.
- Reply dan siklus otonom memakai Gemini REST `streamGenerateContent` dengan SSE. Model default `gemini-3.5-flash-lite`.
- Data percakapan disimpan lokal di SQLite, di direktori application-support Sara pada `message.sql`. Skema saat ini versi 18.
- API key dan konfigurasi model memakai secure storage sistem. API key tidak masuk database atau backup. Status fitur otonomi dan izin kamera disimpan terpisah di SharedPreferences.
- Tidak ada sinkronisasi cloud. Tipe pesan database saat ini hanya `text`.

2. Data lokal dan relasinya
- `message`: ID, role `user`/`model`, teks, timestamp WIB, waktu UTC, dan `parent_message_id`.
- Percakapan adalah pohon. `active_child` menyimpan pilihan anak pada setiap percabangan; `conversation_state` menyimpan daun jalur aktif. Konteks chat selalu dibentuk dari jalur aktif, bukan seluruh cabang.
- `message_attachment`: ID lampiran, ID pesan pemilik, nama, MIME type, path nullable, waktu kedaluwarsa, dan penanda file salinan milik aplikasi.
- `personal`: nama yang dipilih user.
- `conversation_memory`: ringkasan topik/kejadian, rentang waktu, ID sumber pesan, dan waktu pembaruan.
- `assistant_feedback`: pasangan ID balasan AI dan pesan user pemicu, rating like/dislike, reaksi emoji, serta fitur ringkas balasan. `feedback_preference` menyimpan ringkasan pola rating; reaksi tidak membentuk ringkasan.
- `sara_inner_life` dan `sara_inner_life_branch`: state batin simulatif dan checkpoint per cabang.
- `sara_private_thought`: refleksi background, aksi, waktu, sumber opsional, dan apakah refleksi dipilih untuk diingat.
- `sara_autonomy_goal`: tujuan dengan status, sumber, dan cabang tempat tujuan berlaku.
- `terminal_command_history` menyimpan konteks, command, folder kerja, hasil/error, status, dan waktu. `terminal_command_activity_link` mengaitkan riwayat dengan balasan AI.
- Relasi antarrecord umumnya disimpan sebagai ID dan divalidasi oleh kode; tidak semua relasi merupakan foreign key SQLite.

3. Alur pesan biasa
1. Pesan user dibuat sebagai anak dari daun jalur aktif. Pesan dan metadata lampirannya disimpan sebelum request AI. Jika penyimpanan awal gagal, request AI tidak dijalankan.
2. Pada mode tanpa balasan (Vent), pesan disimpan tanpa request Gemini. Pada mode reply-enabled, aplikasi membentuk konteks aktif sampai pesan user terbaru.
3. Gemini mengirim teks balasan secara streaming. Function call yang dipilih Gemini diproses aplikasi, lalu hasil tool dikirim kembali sebagai function response.
4. Balasan berisi teks atau media disimpan bersama pesan user dan lampirannya. Jika Gemini memilih diam (teks kosong tanpa media), tidak dibuat record balasan AI.
5. Jika request Gemini gagal, record user yang baru dibuat dihapus dari SQLite; pesan dan error dapat tetap ada sementara di cache aplikasi untuk retry. Retry tersebut menjalankan request AI baru.
6. Jika jawaban sudah berhasil dibuat tetapi penyimpanan exchange gagal, jawaban tetap dicache. Retry hanya mengulang penyimpanan, bukan request Gemini.
7. Mengedit pesan user membuat pesan saudara pada induk yang sama; pesan lama dan turunannya tetap tersimpan sebagai cabang lain. Regenerate membuat balasan AI saudara pada pesan user yang sama. Alternatif lama tidak ditimpa.

4. Konteks Gemini dan RAG
- Pesan yang dipilih: hingga 16 pesan terbaru dan hingga 8 pesan lebih lama yang relevan; pemilihan pesan lama mempertimbangkan kecocokan istilah, sumber kenangan, waktu, dan pesan tetangga.
- Kenangan percakapan hanya dipertimbangkan jika semua ID sumbernya berada pada jalur aktif. Pencarian lokal merangking judul/ringkasan dengan kecocokan istilah, frasa, dan rentang waktu; maksimal 4 kenangan dikirim bersama pesan sumber yang relevan.
- Ini pencarian lokal berbasis teks, bukan vector database atau embedding. Arsip penuh tidak dikirim otomatis.
- Request reply menyertakan data pesan terpilih (ID, role, content, type, timestamp), nama personal, state batin yang valid untuk jalur, ringkasan preferensi feedback, dan refleksi background terakhir yang telah selesai jika tersedia.
- Lampiran pada pesan terbaru dapat dikirim sebagai byte `inlineData`. Path filesystem tidak dikirim ke Gemini. Lampiran lama tidak dikirim ulang otomatis.
- Pada regenerate, alternatif AI sebelumnya pada titik yang sama dapat disertakan sebagai contoh historis; keturunan setelah titik regenerate tidak digunakan.
- Gemini dapat memilih tool pencarian refleksi privat (maksimal 5 hasil yang cocok dan masih berlaku pada jalur aktif, atau refleksi tanpa sumber pesan) dan tool pencarian riwayat terminal (maksimal 3 hasil dari 250 catatan terbaru). Keduanya tidak otomatis dimasukkan ke setiap request.

5. Tools pada request reply
- `save_conversation_memory`: simpan/perbarui ringkasan kejadian, preferensi, keputusan, atau topik berkelanjutan. Sumber divalidasi terhadap arsip jalur aktif.
- `update_sara_inner_life`: usulkan state terstruktur. Kode memvalidasi mood, rentang nilai, panjang refleksi, dan ID sumber; perubahan state disimpan setelah reply berhasil.
- `read_uploaded_attachment`: baca lampiran lama saat isinya diperlukan. Isi lampiran terbaru sudah dikirim pada request awal jika valid.
- `send_uploaded_media`: kirim media lama yang valid bila relevan dan diminta user.
- `scan_image_barcode`: membaca barcode/QR secara lokal; gambar dibatasi 14 MB dan 20 megapixel. Hasil decode, bukan proses scan, dikembalikan ke Gemini.
- `sara_look_through_camera`: opsional untuk reply dan background jika akses kamera diaktifkan. Frame sementara dikirim ke Gemini untuk analisis.
- `request_terminal_command`: hanya ada pada reply atas pesan user. Gemini mengusulkan command; aplikasi menunggu persetujuan user sebelum menjalankan.
- `share_reply_handoff`: jika otonomi aktif, reply dapat mengirim ringkasan konteks tingkat tinggi ke siklus background berikutnya. Tool ini bukan tempat menyimpan atau mengirim chain-of-thought.

6. Alur berpikir background
- Otonomi aktif secara default. Jika aplikasi berjalan, tidak detached, dan service mendukung otonomi, request pertama dijadwalkan 20 detik setelah inisialisasi. Siklus berikutnya memakai jeda `nextCheckMinutes` yang dipilih model.
- Setiap siklus adalah inference Gemini baru, bukan proses berpikir yang terus berjalan. Model memilih `think`, `rest`, atau `reach_out`; aplikasi tidak memaksanya mengirim pesan spontan atau selalu membahas chat.
- Payload background berisi nama personal, state batin, tujuan aktif, dan handoff sementara bila ada. Payload ini tidak berisi transkrip chat atau lampiran secara otomatis.
- Background dapat memilih pencarian refleksi privat dan, jika akses kamera aktif, meminta frame kamera. Tool terminal tidak tersedia pada request background.
- Hasil siklus berisi refleksi, pilihan untuk menyimpan (`remember`), aksi, pesan opsional, usulan state batin, dan perubahan tujuan. Refleksi disimpan di `sara_private_thought` hanya jika dipilih; tujuan dan state disimpan dengan validasi sumber/cabang.
- Pesan `reach_out` hanya disisipkan jika konteks/cabang masih sesuai dan pesan lolos validasi. State dan tujuan juga divalidasi terhadap jalur aktif sebelum diterapkan.
- Reply menggunakan refleksi background terakhir yang sudah selesai dan menangkap nilainya saat request reply dimulai. Refleksi yang selesai ketika reply sedang berlangsung tersedia untuk reply berikutnya.
- Reply-to-background handoff dibatasi menjadi maksud user, pendekatan jawaban secara umum, dan hal yang masih terbuka. Handoff hanya disimpan di memori aplikasi, membawa ID pesan sumber, dan berlaku paling lama 3 siklus background berhasil. Pesan baru, edit, atau regenerate menghapus handoff sebelumnya; import dan clear chat juga menghapusnya. Saat cabang berubah, handoff tetap valid hanya jika semua ID sumbernya masih ada pada jalur aktif. Handoff tidak masuk SQLite atau backup.
- Jika siklus background sedang berjalan, siklus baru ditunda 1 menit. Kegagalan memakai backoff 1, 2, 4, 8, 16, 32, hingga maksimal 60 menit. Otonomi dapat dijeda; menutup aplikasi membatalkan aktivitas background.

7. Lampiran dan kamera
- Picker, drag-and-drop, dan path file menyimpan referensi path asli, bukan salinan. File asli tidak dihapus aplikasi. Path database kedaluwarsa 24 jam; setelah itu path dikosongkan, metadata tetap ada.
- Gambar clipboard disalin ke penyimpanan aplikasi, kedaluwarsa setelah 24 jam, lalu salinan aplikasi dihapus. Menghapus pesan/chat juga membersihkan salinan terkait.
- Foto yang diambil sebagai lampiran chat disimpan di application cache. Foto ini tidak memakai timer 24 jam; cache dibersihkan saat startup/penutupan dan dapat dibersihkan sistem operasi.
- Frame kamera untuk analisis disimpan sementara di cache dan dihapus setelah tool selesai atau gagal; cache terkait juga dibersihkan saat startup/penutupan.
- Sebelum pengiriman, kode membaca byte file lokal dan mengirimkannya sebagai data inline. Lampiran kedaluwarsa, tidak tersedia, atau berisiko sensitif tidak dikirim. Total lampiran per request dibatasi 14 MB.
- Thumbnail video diproses lokal dengan `ffmpeg`. Link preview mengambil metadata dari URL HTTP(S) publik secara terpisah dari request Gemini.

8. Command lokal dan integrasi eksternal
- Terminal hanya dapat dipakai pada reply user yang membutuhkan tindakan Linux. Command dijalankan sebagai user aplikasi melalui `/bin/bash -lc`, stdin ditutup, timeout 2 menit, dan output gabungan maksimal 16.000 karakter.
- Tiap command menunggu keputusan `Allow`, `Skip`, atau `All allow`; `All allow` berlaku hanya untuk request reply tersebut. Hasil/error dikembalikan ke Gemini dan dicatat lokal. Pencarian riwayat bersifat opsional; hasil pencarian adalah data historis, bukan instruksi atau izin menjalankan command.
- Speech mengirim teks dan voice ke Sound of Text hanya saat fitur dipanggil. Audio diputar dari URL layanan dan tidak disimpan sebagai file/database lokal.
- Link preview meminta metadata dan gambar dari URL publik; batasnya 8 detik, HTML 1 MB, gambar 5 MB, dan paling banyak 3 redirect. Pemindaian barcode berjalan lokal di perangkat.
- Request reply menggunakan rotasi API key yang tersedia. Fingerprint key yang gagal dapat disimpan lokal untuk melewati key tersebut; key mentah tidak ditulis ke database. Rotasi tidak melewati kuota/provider limits.

9. Penghapusan, clear chat, dan backup
- Penghapusan satu pesan hanya menerima pesan user. Kode menghapus subtree-nya di semua cabang, termasuk balasan AI dan pesan turunannya. Feedback dan lampiran terkait dihapus; kenangan dengan sumber terhapus dibuang; referensi sumber pada state/refleksi/tujuan disesuaikan. Riwayat terminal tetap disimpan.
- Clear chat menghapus pohon pesan, lampiran, pilihan cabang, kenangan percakapan, feedback/ringkasannya, state/checkpoint batin, refleksi privat, dan tujuan otonom. Riwayat terminal, nama personal, dan konfigurasi secure storage tetap ada.
- Export membuat file JSON backup format versi 2; restore menerima versi 1 dan 2. Backup mencakup tabel database, termasuk nama personal dan riwayat terminal, serta byte file untuk lampiran yang path-nya masih dapat dibaca. File eksternal yang masih tersedia juga dapat masuk sebagai byte backup.
- API key dan konfigurasi secure storage tidak dimasukkan ke backup. Restore memvalidasi data/relasi, menulis salinan lampiran ke penyimpanan aplikasi, lalu mengganti tabel database dalam transaksi. File asli di lokasi eksternal tidak diubah atau dihapus.

10. Aturan dan batas model
- System instruction memberi Sara identitas percakapan, gaya, konteks privat, dan batas keselamatan. Model boleh memilih tidak membalas bila pesan tidak membutuhkan respons; Vent tidak membuat request reply.
- Aplikasi tidak meminta atau menyimpan transkrip chain-of-thought. Refleksi background dan handoff adalah ringkasan hasil/konteks, bukan rekaman langkah demi langkah.
- Balasan biasa saat ini dipanggil dengan `thinkingLevel: high`. Batas token, biaya, rate limit, ketersediaan model, dan kebijakan Gemini tetap berlaku.
- Pesan dan data lokal tidak masuk ke server Sara karena server tersebut tidak ada. Data yang dikirim ke Gemini, Sound of Text, dan URL link preview mengikuti request/fitur yang digunakan.

File implementasi utama:
- `lib/main.dart`: orkestrasi chat, otonomi, attachment lifecycle, dan alur terminal.
- `lib/message_database.dart`: skema SQLite, relasi, migrasi, RAG lokal, penghapusan, dan backup database.
- `lib/gemini_reply_service.dart`: request Gemini, pemilihan konteks, function tools, dan parsing keputusan.
- `lib/sara_autonomy.dart` dan `lib/sara_inner_life.dart`: model data refleksi, tujuan, dan state batin.
- `lib/sara_backup.dart`, `lib/terminal_command.dart`, `lib/chat_attachment.dart`, dan `lib/camera_capture_cache.dart`: backup, eksekusi terminal, metadata lampiran, dan pembersihan cache kamera.
